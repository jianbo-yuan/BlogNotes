常用串口协议与用途

串口 UART RS-232 RS-485 USB Modbus I2C SPI CAN CAN-FD
机器人理论与技术 机器人通讯系统
发布日期:   2026-08-30

机器人的每一块电路板之间都在”说话”：主控对电机驱动器说”出 3.5 N·m”，IMU 对主控说”我转了 2°”，摄像头说”这一帧图像给你”，夹爪控制器说”我夹住了”。这些对话走的都是串行通讯协议。本文覆盖机器人中最常用的九种：UART、RS-232、RS-485、Modbus RTU、USB、I2C、SPI、CAN、CAN-FD（外加简短的 1-Wire）——每种讲清电气层、协议层、在机器人里的典型用途，并给出 Python demo（帧构造/解析类代码纯 Python 可跑，已实测；硬件读写类标注了所需库与硬件）。

1. 协议全景：一张表先建立坐标

选协议本质是在四个维度做取舍：距离、速率、节点数、实时性：

协议 线数 典型速率 距离 拓扑 机器人用途
UART (TTL) 2 (TX/RX) 9.6k~3M bps <1 m 板内 点对点 调试口、GPS、数传、模块间通讯
RS-232 2~9 (DB9) ≤115.2 kbps ~15 m 点对点 老式设备、力传感器、工控台
RS-485 2 (差分) 10M bps@12m / 100k@1200m 最长 1.2 km 多点总线（32~256 节点） Modbus RTU、传感器总线
Modbus RTU (承载于 RS-485) — — 主从问答 变频器、PLC、智能传感器
USB 4 (差分对+电源) 12M / 480M / 5G+ bps ≤5 m（可级联） 分层星型（主机-设备） 摄像头、调试器、传感器、虚拟串口
I2C 2 (SCL/SDA) 100k~3.4M Hz 板内 <30 cm 一主多从（7 位地址） IMU、编码器芯片、OLED、EEPROM
SPI 4+ (MOSI/MISO/SCK/CS) 1~50+ MHz 板内 一主多从（片选） 高速 ADC/DAC、SD 卡、屏幕
CAN 2 (差分) 1M bps@40m ≤40 m@1M 多主总线 电机驱动器、整机内部总线、BMS
CAN-FD 2 (差分) 仲裁 1M + 数据段 5~8M 同 CAN 多主总线 新一代驱动器、人形机器人关节总线
1-Wire 1 (数据+寄生电源) ~16 kbps ~100 m 一主多从（64 位 ROM ID） DS18B20 温度监测（电机/电池）

两条分界线先记住：

  • 板内 vs 板间：I2C/SPI 是芯片间总线（厘米级），UART/RS-232/RS-485/USB/CAN 是板间总线
  • 实时总线的天花板：CAN/CAN-FD 之上是工业以太网（EtherCAT），见下一篇

2. UART：一切串口的起点

UART 是异步串行收发器：没有时钟线，双方约定波特率各自计时。

帧格式（每个字节一帧）：

  • 常见配置写作 115200 8N1：波特率 115200、8 数据位、无校验、1 停止位
  • 收发双方波特率误差超过 ~2% 就会错位——乱码（如收到 0xFF、0x00 连发）九成是波特率/地线问题
  • TTL 电平（3.3V/5V）不能直连 RS-232/RS-485 设备，需电平转换芯片

机器人用途：调试终端、GPS（NMEA-0183 文本协议）、蓝牙/数传模块、与简单执行器（夹爪、升降模块）通讯。

3. RS-232：经典的单端点对点

UART 的 TTL 电平抗干扰差、距离短。RS-232 定义的是电气层（电平怎么表示 0/1，不改变帧协议），经典接口是 DB9：

要点：

  • 负逻辑电平：−3−15 V 表示逻辑 1（空闲态），+3+15 V 表示逻辑 0——与 TTL 相反且高得多，直连必烧
  • 距离 ~15 m @ 115.2 kbps，点对点，无总线能力
  • 硬件流控 RTS/CTS：高速大数据量时防接收端缓冲溢出；软件流控（XON/XOFF）会污染二进制数据，机器人通讯别用
  • Null-modem 线：两个 DTE（如 PC 对 PC、PC 对传感器）直连要把 2/3 交叉——“接线对了就是不通”的第一嫌疑人

机器人用途：实验室老设备、部分六维力传感器（ATI 老型号）、GPS 接收机、工控机调试口。新设计已逐渐被 USB/以太网取代，但会读它 = 能接手一半的存量设备。

4. RS-485：差分总线，工业长距离主力

RS-485 同样只是电气层，但换成差分传输（A/B 两线电压差编码），质变随之而来：

特性 说明
抗干扰 差分对共模抑制，共模容限 −7~+12 V，可过电机旁边
距离/速率折算 10 Mbps@12 m ↔ 100 kbps@1200 m，机械臂到控制柜绰绰有余
多点总线 经典收发器 32 个单位负载，1/8 负载芯片（如 SP3485）可挂 256 节点
半双工 一对线分时收发（四线全双工版本存在但少）；谁说话由协议层决定
终端电阻 首尾两端各 1 个 120Ω；长线还要偏置电阻保证空闲电平确定

关键工程点——收发方向控制：半双工收发器有 DE（驱动使能）/RE（接收使能）引脚，两种做法：

  1. MCU 用一根 GPIO/RTS 控制：发送前置 DE、发完立刻切回——切换时机晚了自己吃掉从站应答的第一字节（Modbus 排障经典）
  2. 自动收发模块（硬件自收发）：省一根线，但切换延迟由 RC 决定，高速时慎用

机器人用途：机械臂本体到控制柜的长距离指令线、多传感器总线（温度/压力/倾角变送器几乎都说 Modbus RTU over RS-485）、AGV 与充电桩对话。

5. Modbus RTU：RS-485 上的事实标准

Modbus 是主从问答协议：主站发请求帧，指定从站地址 + 功能码 + 数据，从站应答。机器人里大量传感器/变频器/PLC 都说 Modbus RTU。

帧结构（读保持寄存器为例）：

常用功能码：0x03 读保持寄存器、0x06 写单寄存器、0x10 写多寄存器、0x02/0x01 读开关量。CRC-16/Modbus：多项式 0xA001（反射）、初值 0xFFFF、低字节在前发送。

6. USB：即插即用的板间高速通道

USB 不是”串口”，但它是机器人上使用频率最高的板间接口——摄像头、调试器、传感器模块全靠它，且它经常以”虚拟串口”形态伪装成 UART。

架构：分层星型拓扑（主机-设备，最多 5 层 hub），主机轮询调度，设备无主动权。速度档位直接决定用途：

档位 速率 机器人用途
Full Speed 12 Mbps 虚拟串口（CDC-ACM）、HID 键鼠
High Speed 480 Mbps 相机（UVC）、USB-UART 桥、数据采集卡
SuperSpeed 5~20 Gbps 高帧率相机、USB SSD

与机器人最相关的三类设备形态：

  1. CDC-ACM / USB-UART 桥（FTDI、CP210x、CH340）：插上就出现 /dev/ttyACM0 或 /dev/ttyUSB0（Windows 是 COMx）——上层按纯 UART 编程（本文 2.2 节代码直接可用），这是”USB 伪装成串口”的最常见形态
  2. UVC 相机：标准视频类，OpenCV cv2.VideoCapture(0) 直接打开
  3. 专用 USB 外设（力传感器、雷达）：厂商 SDK 走 libusb 批量传输

USB 工程三条铁律：

  • 设备名漂移：ttyUSB0 会在重新插拔后变成 ttyUSB1。按序列号固定：Linux 写 udev 规则 SUBSYSTEM=="tty", ATTRS{idSerial}=="A50285BI", SYMLINK+="myimu"，之后永远用 /dev/myimu
  • 带宽共享：同一 USB2 root hub 上两个 480Mbps 相机互相挤兑——多相机分开插不同 root（lsusb -t 看树）
  • 延迟下限：USB 主机调度以 1ms 帧为单位（HS 用微帧 125µs），别指望 USB 做硬实时控制环——它是数据通道，不是控制总线

7. I2C：两线传感器总线

一根时钟 SCL + 一根数据 SDA，开漏输出 + 上拉电阻，线与逻辑天然支持多从站仲裁。

传输流程：起始条件（SCL 高时 SDA 下拉）→ 7 位从站地址 + 读写位 → 从站 ACK → 寄存器地址 → 数据……→ 停止条件。所有从件都在同一条线上听自己的地址。

关键概念：

  • 地址冲突：两个器件地址撞了（常见 0x68 IMU 之争）要么改地址引脚，要么换总线
  • 时钟拉伸（clock stretching）：从件忙时拉住 SCL 让主站等——慢速 EEPROM 页写入时靠它
  • 上拉电阻：2.2k~10k，总线越长/速率越高取越小；忘加上拉是 I2C 排障第一名
  • 速率档位：标准 100kHz / 快速 400kHz / 快速+ 1MHz / 高速 3.4MHz——速率越高，可走的线越短

机器人用途：MPU6050/BNO055 IMU、AS5600 磁编码器、OLED 小屏、EEPROM、ToF 测距（VL53L0X）、PCA9685 舵机驱动板——“读一两个寄存器”型低速器件全是 I2C。

8. SPI：高速四线

为速度而生：全双工、带时钟线、每挂一个器件加一根片选 CS：

信号 方向 作用
SCK 主→从 时钟（速率可达几十 MHz）
MOSI 主→从 主出从入数据
MISO 从→主 从出主入数据
CS/NSS 主→从 低有效，选中谁谁应答

两个参数决定时序模式：CPOL（空闲时钟电平）× CPHA（第几个边沿采样）= 模式 0~3。器件手册写明支持哪种，主从配错读到的是移位错乱的鬼数据。

机器人用途：高带宽 ADC/DAC（力/触觉采样）、SD 卡、SPI-Flash、TFT 屏、高速 IMU（如 ICM-42688 以 SPI 跑 8kHz+ 用于飞控/平衡控制）。

xfer2 一次事务自动拉低/释放 CS——SPI 的”事务”语义靠 CS 包裹，拆开读写就不是原子事务了。

9. CAN：机器人内部总线之王

CAN 把 RS-485 的差分物理层 + 一套多主仲裁、错误 confinement、短帧协议打包，成为电机驱动器与整车的事实标准（无人机、平衡车、DexHand 类灵巧手的指间总线常见 CAN）。

核心机制三件套：

  1. 标识符仲裁（CSMA/CD 无损）：帧 ID 同时是优先级。多个节点同时发，逐位比较，发 0 者胜（显性位）；仲裁失败的自动退让不损坏总线——ID 越小优先级越高
  2. 短帧：标准帧 11 位 ID + 0~8 字节数据（DLC），1Mbps 下单帧 ~100 µs，最坏延迟有界——实时性的来源
  3. 五级错误管理：CRC/ACK/位错误检测，故障节点自动”离线”不拖死总线

机器人典型用法：每个驱动器一个 ID，控制帧（目标位置/力矩）+ 反馈帧（实际位置/温度），ODrive、MIT Cheetah 风格的迷你驱动器都是 CAN 设备。

10. CAN-FD：CAN 的带宽扩容版

经典 CAN 的 8 字节载荷在复杂驱动器上捉襟见肘——“位置+速度+kp+kd+前馈力矩+使能+温度限幅”一帧装不下，只能拆两帧发还破坏原子性。**CAN-FD（Flexible Data-rate）**三个改动解决它：

维度 经典 CAN CAN-FD
载荷 ≤ 8 字节 ≤ 64 字节
速率 全帧统一 ≤ 1 Mbps 双速：仲裁段 ≤1 Mbps，数据段切到 5~8 Mbps（BRS 位标识切换）
CRC 15 位 17/21 位（更长帧要更强校验）
帧间隔 3 位 IFS 更长的 CRC/EOF 序列

双速的巧思：仲裁阶段必须慢（节点间逐位比较要等传播延迟），但一旦仲裁完成、总线上只剩一个发送者，数据段立刻加速——既保住 CAN 的确定性仲裁，又把吞吐提了数倍。

机器人为什么爱它：

  • MIT-Cheetah 风格全状态指令帧（5×float32 = 20 字节）+ 反馈帧（位置/速度/力矩/温度/错误码）一帧一个，原子且高频（1kHz 指令下发不再是带宽瓶颈）
  • 固件升级走总线：64 字节块 + 高数据速率，几十个关节的固件 OTA 从”半小时”变”几分钟”
  • 一帧带回完整诊断信息（版本号+错误码+温度），运维体验质变

兼容性铁律：经典 CAN 控制器收到 FD 帧会报格式错误——总线上要么全是 FD，要么全是经典，混布是事故（新驱动器默认 FD、老主控是经典 CAN，这个坑天天有人踩）；收发器也必须选 FD 型（数据段边沿更快，普通收发器振铃）。

11. 1-Wire：单线温度监测（简短）

一根数据线（寄生供电从数据线取电）+ 一条地线，速率仅 ~16 kbps，但每个芯片出厂带全球唯一 64 位 ROM ID，一主多从免地址冲突。机器人里几乎只有一个用途：DS18B20 温度传感器贴电机/电池测温。

12. 选型与踩坑速查

选型决策树：

踩坑 Top8（每条都是真实事故）：

  1. 共地：UART/单端信号两板不共地 = 随机乱码。先接 GND 再接信号
  2. 波特率/速率/模式三对齐：UART 波特率、SPI 模式、CAN 位速率——主从不一致症状全是”收到鬼数据”
  3. RS-485 收发使能：半双工，发送完要立刻切回接收，否则自己吃掉从站应答；首尾终端电阻各一个（不是每个节点都加）
  4. Null-modem：两个 RS-232 DTE 直连要 2/3 交叉
  5. I2C 忘上拉 / 地址冲突：i2cdetect 一扫便知
  6. USB 设备名漂移：udev 按序列号绑定，别让 ttyUSB0/1 赌运气；USB 不是实时总线，控制环别走它
  7. CAN 终端电阻：首尾各 120Ω，大电流电机启停时的鬼帧九成是它；CAN 与 CAN-FD 不可混布
  8. 线束分类走线：电机动力线与信号线分开扎束、差分线用双绞——EMI 是”偶发诡异 bug”的最大来源

13. 总结

一张卡片带走：

协议 一句话
UART 异步点对点，约定波特率，自定义帧 + 校验和
RS-232 单端 ±12V 点对点，负逻辑，老设备接口
RS-485 差分电气层，公里级距离，多点半双工总线
Modbus RTU RS-485 上的主从问答，CRC16 是身份证
USB 即插即用分层星型；虚拟串口是它最常见的伪装；数据通道非实时
I2C 两线一主多从，7 位地址，传感器默认选择
SPI 四线全双工高速，CPOL/CPHA 定时序，事务靠 CS
CAN 差分多主、ID 即优先级、短帧有界延迟，驱动器标准
CAN-FD 64 字节 + 双速（仲裁 1M/数据 5M+），全状态指令帧与固件 OTA 的载体
1-Wire 单线寄生供电，64 位唯一 ID，DS18B20 测温专用

所有协议的调试方法论是同一个：示波器/逻辑分析仪看物理层 → 十六进制打印看帧层 → 按协议文档逐字段对。帧构造/解析的 Python 代码（本文 2.1/5.1 节）可以脱离硬件先写好、用向量测好，等硬件到位直接对接——这也是机器人驱动开发里”软硬并行”的标准做法。需要微秒级同步与更高带宽时，进入EtherCAT 的世界。
